# Build notes

## Why net6.0 (not netstandard2.1 / net472)

BepInEx 6 IL2CPP plugins run on the .NET 6 runtime that BepInEx itself hosts, and the
Il2Cpp interop assemblies it generates are net6.0. Verified on this game:

- BepInEx ships `mscordaccore_amd64_amd64_6.0.722.32202.dll` -> .NET 6.0.7
- BOMBANANA Library's own pdb path is `.../obj/Release/net6.0/BOMBANANA.Library.pdb`
- BepInEx's official IL2CPP template hard-codes `<TargetFramework>net6.0</TargetFramework>`
  (its `template.json` still carries a stale `netstandard2.1` default; the csproj does not)

netstandard2.1 / net472 will compile but the loader rejects the plugin at runtime.

## Prerequisites

The .NET SDK, 6.0 or newer. If `dotnet` is not on your PATH, either put it there or edit the
lookup at the top of `pack.ps1`; it falls back to `%USERPROFILE%\.dotnet\dotnet.exe`.

## Build and package

```powershell
# from the repository root
powershell -ExecutionPolicy Bypass -File pack.ps1
```

That builds the plugin, deploys it into the r2modman profile, and writes
`dist\EndlessEasy-<version>.zip` ready for Thunderstore.

Building alone:

```powershell
dotnet build BombananaEndlessEasy\BombananaEndlessEasy.csproj -c Release
```

Output: `BombananaEndlessEasy\bin\Release\net6.0\BombananaEndlessEasy.dll`.

## Where the DLL gets deployed

`Directory.Build.props` derives the plugin folder from `%APPDATA%` using the standard
r2modman layout, so a fresh clone needs no edits:

```
%APPDATA%\r2modmanPlus-local\Bombanana\profiles\Default\BepInEx\plugins
```

If your install differs (different profile name, or Thunderstore Mod Manager instead of
r2modman), copy `Directory.Build.user.props.example` to `Directory.Build.user.props` and set
the paths there. That file is gitignored, so machine-specific paths never reach the repo.

Override for one build without editing anything:

```powershell
dotnet build -c Release -p:BombananaPluginsDir="D:\somewhere\BepInEx\plugins"
```

## NuGet sources

The csproj adds BepInEx's own feeds through `RestoreAdditionalProjectSources`:
`https://nuget.bepinex.dev/v3/index.json` and `https://nuget.samboy.dev/v3/index.json`.

`BepInEx.Unity.IL2CPP` is referenced as the floating `6.0.0-be.*`. To pin it to exactly the
build you run, use the precise version (for example `6.0.0-be.755`) and restore again.

## Reference strategy

| Reference | Source | Notes |
| --- | --- | --- |
| BepInEx.Unity.IL2CPP | NuGet, `IncludeAssets="compile"` | Always available |
| BOMBANANA.Library | the installed DLL, `<Private>false</Private>` | Always available |
| Assembly-CSharp / UnityEngine | `BepInEx\interop` | Generated by BepInEx on the game's first launch |

`<Private>false</Private>` matters: the game and the mod manager already ship these assemblies,
so copying them into the package would load a second copy and break the plugin.

## Things to watch for

1. `HarmonyLib` arrives transitively via `BepInEx.Unity.IL2CPP`. If it ever cannot be found,
   add an explicit `HarmonyX` `PackageReference` matching the version BepInEx bundles.
2. If `dotnet build` complains about `BOMBANANA.Library` or `Nullable`, the SDK is older than
   the Library; upgrade the SDK.
3. `BepInEx\interop` not existing before the game's first run under BepInEx is normal.
